INSP-12 — Route conflict: a cost cannot be both prepaid and capitalized 4 exception(s)

Gaurav 2026-08-17 (DA-14): the chosen account decides the route, and a service period only means something on the expense side of the fork. Prepaid = the cost has not become an expense YET (park in 1300 Prepayments, release monthly into the P&L). Capitalized = it is already an asset (park in the asset account, amortize by policy through the register). A schedule releasing into a non-P&L account asks the system to run both: the money shuffles between two assets and never reaches the P&L, while the register separately ages it — profit is overstated and the same cost risks being charged twice. Four live schedules did exactly this (3 releasing into 1710 Technology Development, 1 into 2410 Convertible Notes). The invoice gate now ignores a service period on a non-expense account and the release engine refuses these, so this rule catches history and anything written around the services.

INSP-13 — Spend parked on the balance sheet but never scheduled CLEAN

Gaurav 2026-08-18: both routes into a schedule run off an APPROVAL — the invoice approval creates the prepaid spread, and the registrar picks up capitalized spend that has a bank transaction behind it. A MANUAL journal has neither, so the cost parks on the balance sheet and nothing ever ages it: expense understated forever, profit overstated forever, and no one notices because the balance sheet still balances. Two shapes: (a) a debit into a policy-covered asset account with no register row for that journal — note the register requires a bank transaction today (transaction_id is NOT NULL), so a manual journal cannot be registered AT ALL, it is only reported; (b) a debit into 1300 Prepayments with no release schedule behind it. INSP-10(b) cannot see either: it only fires when a policy has ZERO register rows, so one unscheduled journal among many scheduled ones is invisible to it.
