Categorization Engine — How It Works (flow #1, expanded) · input = a Pending bank transaction → output = a posted JE

Phase 0

Internal-transfer pairing

If this transaction is the counterpart of an AWAITING_MATCH internal transfer (e.g. OCBC → Wise), pair the two sides (±2% amount, ±5 days).

→ both sides become Matched, sharing one JE. Otherwise continue.

Phase 1

Counterparty enrichment

L1 deterministic (exact/substring on name + aliases) → L2 fuzzy (rapidfuzz ≥ 88) → L3 LLM (one batched Claude call for the rest). Links a counterparty_id.

→ needed so the next phases (invoices, payroll, rules) can act on the counterparty.

Phase 1.5

AP invoice knock-off  ← this is where existing invoices come in

If the counterparty has open AP invoices, run 3-case matching:

Case 1 — invoice ref in description + amount ≈ remaining (±2%) + date OK → match (invoice's COA wins) → Dr 2000 AP / Cr Bank
Case 2 — no ref but amount ≈ remaining → match the oldest invoice (FIFO) → Dr 2000 AP / Cr Bank
Case 3 — amount matches no invoice → skip → Phase 4 asset-parks to 1300
No invoices → skip to Phase 4.  (Cross-entity invoice → paired IC JEs.)

Phase 2.5

Payroll knock-off

For outgoing payments, match a POSTED payroll run (net salary or CPF, ±2% amount, ±7 days, any entity).

→ same-entity: links the existing payroll JE. Cross-entity: creates paired intercompany JEs.

Phase 4

Accounting classification (the fallback ladder)

4A — Rules engine: first matching rule by priority (AND logic on counterparty type / text / amount / currency) → JE.
4B — Counterparty default: use default_account_code if set → JE.
4C — Asset parking: the Case-3 amount-mismatches → Dr 1300 / Cr Bank.
4D — AI classification: Claude Haiku suggests a COA + confidence — ≥ 0.80 → JE; < 0.80 → Needs Review.

→ if none of these fire, the transaction stays Pending in the manual queue.

Status lifecycle:   Pending  →  { Awaiting Match · Matched · Needs Review }  →  Reconciled (human-confirmed).   On approval, the engine also learns the bank description as a counterparty alias (better L1 matching next time).
Every path above ends by posting a balanced JE into the general ledger (or parking the txn for manual review). Live: 244 active rules across 730 transactions → 245 JEs.
