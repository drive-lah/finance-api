## Codebase Patterns
- Python 3.14 with Flask 2.x application factory pattern
- Virtual environment at ./venv (excluded from git)
- Tests using pytest with pytest-flask plugin
- Configuration via .env file (template at .env.example)
- Project structure: src/ for source code with subdirectories (routes, services, models, utils)
- Requirements managed via requirements.txt
- Database: SQLAlchemy 2.x ORM with PostgreSQL
- Validation: Pydantic 2.x
- Database sessions: Use `get_db()` generator or `db_session()` context manager from src/database.py
- Migrations: Alembic in migrations/ directory, run with `alembic upgrade head`
- DB config supports both DATABASE_URL or individual DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD
- Connection pooling enabled by default with QueuePool (configurable via env vars)
- Models: SQLAlchemy 2.x style with Mapped[] type hints, Base imported from src/database
- Enums: Use native_enum=False for VARCHAR storage (cross-DB compatible)
- Schemas: Pydantic 2.x with field_validator, model_config = {"from_attributes": True} for ORM compatibility
- All models have to_dict() method for JSON serialization
- Routes: Flask Blueprints in src/routes/, register in app.py with app.register_blueprint()
- Services: Business logic in src/services/ with singleton instances (e.g., entity_service)
- API responses: Use EntityResponse.model_validate(entity).model_dump() to convert ORM → JSON
- Route testing: Mock get_db in routes module with patch('src.routes.MODULE.get_db', mock_get_db)
